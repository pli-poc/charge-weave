# Ontology authoring service (under construction)

This package currently exposes workspace reads, class search, source-grounded class inspection, baseline comparison and bounded draft class, property and relationship commands over MCP Streamable HTTP. Semantic writes and class inspection use the repository's Python authoring adapter and shared generator parser. Reusing an existing global property name is deliberately rejected until impact-aware editing is supported. It is not yet the complete modelling studio or a publication service. Node 22.18 or newer and Python are required.

From this directory, run `npm ci`, then create a workspace from the committed repository baseline with `npm start -- --create-workspace`. Record the returned workspace ID. The import reads `model/domain.schema` from Git at HEAD; uncommitted changes are not included. The default SQLite database is `workspaces.sqlite` in this directory; set `CHARGEWEAVE_WORKSPACE_DB` to change it and `CHARGEWEAVE_REPOSITORY` to select the local checkout. Run `npm run doctor` after configuring the workspace and token to check local prerequisites without printing credentials.

Set `CHARGEWEAVE_WORKSPACE_ID` to the returned ID and `CHARGEWEAVE_DRAFT_TOKEN` to a long random secret of at least 32 bytes, then run `npm start`. The server listens only on `127.0.0.1:4317` (override the port with `CHARGEWEAVE_PORT`). MCP clients send the token in the `Authorization: Bearer` header. Do not commit or share the token. To permit a browser origin, explicitly set `CHARGEWEAVE_BROWSER_ORIGIN` to its exact origin; other origins are rejected. This local process grants draft access only to the configured workspace; it is not a reviewer or publisher credential.

For the local same-origin studio, install the locked dependencies in `client-runtime` and `website`, then run `npm run build --prefix ../website` from this directory. Set `CHARGEWEAVE_PAIRING_CODE` to a distinct random secret of at least 32 bytes before starting the service. Open the printed `/charge-weave-app/modelling/` URL and enter that code in **Pair local studio**. The code expires five minutes after service startup, is single-use, and is invalidated after five incorrect attempts. The resulting HttpOnly, SameSite=Strict session lasts up to eight hours, is scoped to the configured workspace, and is removed by a successful **Disconnect** or service restart. The browser automatically resumes an existing session after a reload. Never put the code or bearer token in a URL or commit them. The service serves only supported files under `website/dist`; set `CHARGEWEAVE_WEB_DIST` to another built directory if needed.

For example, in a private PowerShell session, generate a fresh code with `$env:CHARGEWEAVE_PAIRING_CODE = [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))`. Read that environment variable locally when entering the code. Generate the separate draft bearer credential independently. These local sessions can inspect review readiness but cannot accept or publish; production identity and per-user grant management remain unimplemented.

An optional distinct `CHARGEWEAVE_REVIEWER_TOKEN` (at least 32 bytes) exposes review-readiness inspection in addition to draft operations for that same workspace. It reports exact-digest checks and missing gates; it cannot accept or publish a change. This is an interim local credential, not the planned browser pairing session or per-user grant management.

MCP request bodies are limited to 512 KiB. A slow event consumer is disconnected and should reconnect using its last event cursor. On a normal shutdown the service closes event streams and waits for active validation jobs before closing the database; an abrupt process termination leaves interrupted jobs for inspection on restart.

The authenticated `GET /events?workspaceId=<id>&after=<sequence>` endpoint streams committed changes as server-sent events. Reconnect with the last event ID to replay later events. Each event includes the previous sequence for the same workspace; global sequence numbers may skip because other workspaces share the store. An unknown cursor returns 409 and requires a new snapshot. This feed is read-only; semantic changes still use MCP. Clients must deduplicate events and recover from a snapshot if they detect a gap or cannot apply a delta.

Run `npm test` to exercise the store and MCP transport. Workspace creation is currently a local command, not an MCP tool. Review decisions and publication are not yet implemented.

Validation requires Python, Git, tar, and the pinned dependencies in `requirements.txt`. Set `CHARGEWEAVE_PYTHON` to the Python executable when it is not on PATH. Checks materialize the pinned baseline in a temporary directory and record the input revision and digest. The structural profile runs `tools/build.py`; the reference profile runs full generation, SHACL reference validation, business-rule negative fixtures and structural boundary tests. The acceptance profile also checks generated artifacts and runs the repository release gates individually; it requires Java and can take a long time. It requires a baseline exposing the supported release-gate catalogue. Passing these checks does not establish all independent acceptance evidence or authorize publication. Incomplete jobs are marked interrupted on restart.

Only one validation job may run per workspace. Retrying the same operation ID returns the original job; a different request is rejected while that job is active. Each completed step is retained in the bounded job output. Validation compares tracked model, benchmark, requirements, test and tool inputs against their pre-generation bytes, excluding the repository's known generated outputs. A substantive source rewrite fails the check rather than attributing the result to the earlier draft.

Completed jobs can be read through `ontology_evidence_get` using the job ID as the evidence ID. The response identifies the baseline commit, checked revision, source digest, scope, freshness and individual step outcomes. An interrupted or cancelled job is evidence of that outcome, not a passing validation. The service does not yet retain full generated artifacts or establish all required acceptance evidence.

`ontology_temporal_view_get` and the studio's temporal panel show the selected class's explicit time and window fields together with its class policy from the pinned baseline. The policy file is checked against the workspace source manifest; a missing policy is shown as missing and is not inferred for a new class. Legacy workspaces without a complete source manifest cannot use this view. The displayed model revision and baseline policy are separate identities; the panel does not infer business valid-time or known-time semantics from field names.

`ontology_responsibility_view_get` and the responsibility panel match declared or inherited fields against the server's versioned, partial mapping of exact owner, property and target triples. Each binding retains its source location and mapping version. The mapping is presentation metadata, not a new ontology assertion or an exhaustive responsibility analysis; an empty result means only that no curated binding matched.

The draft comparison includes a unified patch for `model/domain.schema` alongside semantic summaries and before/after source. The patch is computed from the exact stored baseline and current draft; generated artifact and other source-owner patches are not yet included.

Workspaces created by the local bootstrap use digest version 3: a SHA-256 identity over the adapter version, immutable baseline commit and a path-sorted SHA-256 manifest of tracked model, benchmark, requirements, test and tool inputs, with the current schema overlay substituted. Validation compares that manifest to its materialized inputs before running checks. Known generated outputs are excluded; additional source owners and non-ontology application inputs still need explicit inclusion before publication. Existing version 1 and 2 workspaces retain their original digests and receipts for recovery, and review readiness flags the missing complete manifest. Create a new workspace to use version 3.

For version 3, semantic writes and source-grounded inspection require the local authoring adapter and schema parser to match the workspace's pinned manifest. If either is missing or differs, those operations stop with a compatibility error; create a new workspace from the current commit after reviewing the existing draft. This does not automatically migrate draft changes or replace a review.

Cancellation is cooperative: the running fixed check is allowed to finish, then the job stops before the next check and is marked `cancelled`. A cancelling job continues to occupy the workspace validation slot. Cancellation does not promise immediate termination of a running child process.

`node --test test/demo.test.js` runs a synthetic two-client maintenance scenario against the committed `HEAD` schema: it discovers existing terms, adds a planned maintenance class, typed relationships and controlled lifecycle values, refines and undoes a definition, restarts the service, and retries the original operation. It does not yet demonstrate acceptance, publication, or exact-commit CI status.
